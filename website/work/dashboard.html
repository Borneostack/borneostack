The problemThe problem

An owner who wants to know whether costs are moving has to visit a different government page for each number, each with its own download, format and update day. Most people stop checking.

What we builtWhat we built

One page that shows 11 series from five datasets, with the latest value, the change on the previous period and the date of each value. Sabah is set against Malaysia where the data allows it. A "show as table" switch under each chart gives the same numbers as text.

How it worksHow it works

What happens, in order.

  1. Step 1

    Every morning it reads five public sources

    At 06:00 Kota Kinabalu time the system asks the government open-data service for the newest figures: fuel prices, the US dollar, inflation, unemployment and economic growth.

  2. Step 2

    Each figure is checked and saved once

    A figure is checked, then saved with its date. Running the job twice never makes a duplicate. If one source is down, the others still update and that one keeps its last figures.

  3. Step 3

    The page opens with figures on it

    The page already holds a saved copy, so there is something to read at once. It then fetches the latest figures and swaps them in. If the system cannot be reached, the saved copy stays and the page says which date it is from.

  4. Step 4

    You can see what happened each day

    A log lists every daily run and whether each source worked, so a missing update is visible instead of silent.

What a client project addsWhat a client project adds

The public datasets are replaced by your own: a Google Sheet, an accounting export, a SQL database or a supplier portal. We add the figures your team actually watches, alerts by email or WhatsApp when one crosses a limit you set, a login for staff, and your branding. You get the source of every number, as here.

For technical readers: the stack and the limits

Stack. One Cloudflare Worker and a D1 database (SQLite), both on the free plan, and a Next.js page exported as static files. The charts are drawn by hand in SVG, with no chart library. No AI is used anywhere on this page.

The daily job. A cron trigger starts the Worker at 22:00 UTC. It makes eight requests to api.data.gov.my, 16 seconds apart, because that API allows four requests a minute. The job takes about two minutes, almost all of it waiting; Cloudflare allows a cron-triggered Worker 15 minutes. Each request asks only for the newest few rows. A figure is stored by series and date, so a second run changes nothing.

The snapshot. At the end of each run the database assembles the whole snapshot as one piece of JSON, and that text is stored in one row. A visitor's request returns the stored text without rebuilding it, because the free plan gives a Worker 10 ms of CPU time per request. The answer is also cached for 15 minutes at the edge, and each visitor is limited to 60 requests a minute. A second endpoint returns the log of the last 14 runs.

Numbers. 11 series and 2,476 figures at the time this page was built.
